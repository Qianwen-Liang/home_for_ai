# 工具契约规范（Tool Contract Specification）v1.0

> 编号：1.1 ｜ 制定日期：2026-10-30
> 依据：MCP 官方规范（2026-07-28）Tools 章节、Hypothesis 属性测试思想
> 适用范围：`agent1.ALL_TOOLS` 中全部已注册工具（当前 16 个），以及 legacy 工具恢复后

---

## 一、为什么需要契约

### 实测缺口（探测结论）
| 项 | 现状 | 标准要求 |
|----|------|---------|
| 工具命名合规 | 16/16 ✅ | — |
| `inputSchema` | 16/16 ✅ | 必填 |
| **`outputSchema`** | **0/16** ❌ | 可选但推荐 |
| **`annotations`** | **0/16** ❌ | 可选但推荐 |
| 错误类型 | 30 种各自为政 | 需分层归类 |
| 参数校验 | 各工具自行实现 | 需统一验证 |

**结论**：工具契约在"输入"侧基本合规，在"输出/行为/错误"侧完全空白。

## 二、工具定义契约（对齐 MCP 标准）

### 2.1 必填字段

| 字段 | 类型 | 约束 |
|------|------|------|
| `name` | string | 1–128 字符；仅 `A-Za-z0-9_-.`；区分大小写；全局唯一 |
| `inputSchema` | JSON Schema object | 描述参数结构；默认草案 2020-12 |

### 2.2 可选字段

| 字段 | 类型 | 约束 |
|------|------|------|
| `title` | string | 人类可读名称 |
| `description` | string | 功能描述，影响模型选择准确率 |
| `outputSchema` | JSON Schema | **提供则结果必须符合**，客户端需校验 |
| `annotations` | object | 描述行为；**默认不可信**，除非来自可信源 |
| `icons` | array | 图标元数据 |

### 2.3 `annotations` 推荐字段（本系统约定）

```json
{
  "idempotent": true,      // 幂等：重复调用结果一致
  "readOnly": false,       // 只读：不产生副作用
  "destructive": false,    // 破坏性：可能删除/覆盖数据
  "slow": false,           // 慢操作：预期 >1s
  "largeOutput": false     // 大结果：可能超上下文预算
}
```

## 三、参数契约

### 3.1 类型约束
仅允许 JSON Schema 基础类型：`string` / `integer` / `number` / `boolean` / `object` / `array`。

### 3.2 必须满足的性质（全域性，非个例）

> 对**任意**参数输入 $x$，工具入口必须满足以下性质之一，**不得**抛出未捕获异常：

| # | 性质 | 说明 |
|---|------|------|
| P1 | 正常执行 | 合法参数 → 返回结果字符串 |
| P2 | 业务拒绝 | 非法参数 → 抛出已知错误类型，或返回结构化错误串 |
| P3 | 不崩溃 | **绝不**抛出 `TypeError` / `KeyError` / `AttributeError` 等未捕获异常 |

### 3.3 边界输入清单（替代 hypothesis 的默认策略补充）

契约测试必须覆盖以下 6 类边界输入：

| 类别 | 示例 |
|------|------|
| 缺失 | 不传必填参数 |
| 类型错误 | 应传 integer 传 string、应传 string 传 null |
| 越界 | 负数、极大值（如 `2**63`）、零 |
| 空值 | `""`、`{}`、`[]` |
| 超长 | 1MB 字符串 |
| 特殊字符 | 路径穿越 `../`、NUL `\x00`、控制字符、Unicode 边界 |

## 四、错误契约（分层对齐 MCP 双机制）

### 4.1 三层分类

| 层级 | 语义 | 对应 MCP | 处理策略 |
|------|------|---------|---------|
| `RETRYABLE` | 网络/超时/限流，可重试 | Tool Execution Error | 自动重试（指数退避） |
| `FATAL` | 配置/环境/不可恢复 | Protocol Error | 上报 + 诊断 + 中止 |
| `REJECTED` | 业务拒绝（路径不存在/参数越界） | Tool Execution Error | 交模型自纠 |

### 4.2 错误对象契约

所有工具错误必须满足：
- 继承 `RuntimeError`（保留与现有代码兼容）
- 携带 `category`（三层之一）与 `error_code`（稳定标识）
- **保留原始信息**：分类不丢弃细节

### 4.3 现状映射（30 种 → 三层，示例）

| 现有错误 | 归类 |
|---------|------|
| `RunnerError`（路径不存在/参数超限） | `REJECTED` |
| `ReadToolError` / `WriteToolError` | `REJECTED` |
| `WebSearchError`（网络失败） | `RETRYABLE` |
| `KnowledgeStoreError`（内部状态） | `FATAL` |
| `CapsuleError` | `FATAL` |

> 完整映射表在步骤 4.2 建立；本步仅需测试"错误必须可归类"。

## 五、结果契约

### 5.1 返回类型
工具 handler 返回 `str`。非字符串结果视为契约违规。

### 5.2 大结果阈值
| 阈值 | 行为 |
|------|------|
| ≤ 20,000 字符 | 全量返回 |
| > 20,000 字符 | **必须**走"摘要 + 落盘句柄"路径 |

> 步骤 4.3 将统一为全局 `ContextBudget`；本步按现有 20,000 字符阈值验证。

### 5.3 错误结果
失败时返回以 `❌` 或 `⚠️` 开头的结构化错误串，或抛出契约内已知错误类型。

## 六、契约断言清单（供 1.2 实现）

| 断言 ID | 名称 | 性质 |
|---------|------|------|
| **C1** | `schema_compliance` | 工具定义符合 MCP 必填字段与命名规则 |
| **C2** | `param_validation` | 6 类边界输入下满足 P1/P2/P3 |
| **C3** | `error_contract` | 错误必为已知类型且（后续）可归类 |
| **C4** | `no_exception_leak` | 任意输入绝不抛未捕获异常 |
| **C5** | `result_type` | 返回值必为 `str` |
| **C6** | `large_result` | 超阈值必须走摘要路径 |

**验收目标**：16 工具 × 6 断言 = **96 个契约检查点全部通过**（或明确登记豁免）。

---

## 七、豁免机制

某些断言对特定工具不适用（如 `self_check` 无必填参数，C2 的"缺失必填"不适用）。
豁免需在 `contract_baseline.json` 中登记：
```json
{"tool": "self_check", "assertion": "C2.missing_required", "reason": "该工具无需填参数"}
```
