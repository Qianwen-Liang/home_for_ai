# 强化版多智能体论文协作功能 — 能力评估报告

> 生成时间：2026-08-16
> 评估对象：`research/paper_collab.py`（投稿人↔审稿人协作）+ `offline_research` 工具集成
> 评估方式：真实端到端运行 + 人工审查产出物

---

## 一、功能概述

实现了一个「投稿人（Writer）↔ 审稿人（Reviewer）」多轮对话协作的论文生成功能，融合了：

| 借鉴来源 | 借鉴的设计 |
|:---|:---|
| AutoGen | Writer-Reviewer 多轮对话循环、Critic 角色 |
| MetaGPT | 角色 SOP + 结构化审稿表（强制 JSON 输出）|
| ChatDev | 反思机制、阶段产物审查反馈 |
| CAMEL | 角色化 prompt（Inception Prompt）|
| 离线自主智能体（AutoGPT/ARIS）| 检查点持久化、收敛/终止条件 |

**核心机制**：
1. Writer 撰写初稿
2. Reviewer 输出结构化评审（`verdict/score/strengths/weaknesses/suggestions`）
3. Writer 根据意见逐条修改
4. 循环直至收敛（accept 或 score≥8 或达到最大轮数）

---

## 二、实际验证结果

用主题「基于检索增强的多智能体协作问答系统」跑真实端到端（2 轮）：

| 指标 | 结果 |
|:---|:---|
| 初稿长度 | 8865 字符 |
| 最终论文长度 | **16301 字符**（结构完整）|
| 第 1 轮评审 | revise, score=5, 6 缺点 6 建议 |
| 第 2 轮评审 | revise, score=6, 4 缺点 5 建议 |
| 论文结构 | 摘要/引言/相关工作/方法/实验/结论/参考文献 齐全 |
| 内容要素 | 数学公式、算法伪代码、实验表格、消融分析、错误分析、17 条参考文献 |

**评审轨迹证明协作有效**：第 1 轮审稿人指出"基线不公平、缺显著性检验、消融表截断"等问题；第 2 轮审稿人确认"已补全表格、基线更全面、新增显著性检验"——说明 Writer **真的采纳并执行了** Reviewer 的意见，而非空转。

## 三、能力强弱（客观评估）

### ✅ 强项

1. **真正的多轮互评闭环**：不是单次生成，而是"写→批→改→再批"的迭代，且修改是可验证的（评审分数 5→6，审稿人确认问题被解决）。
2. **结构化评审**：强制 JSON 审稿表，避免了"模糊的夸奖式评审"，审稿人能给出**具体、尖锐、可执行**的意见（如"Self-RAG 为简化版本可能低估基线""消融表措辞应为'独立配置'而非'独立训练'"）。
3. **产出论文结构完整**：能覆盖学术论文的标准章节，含公式、伪代码、表格、引用。
4. **离线可运行**：后台进程 + 进度持久化 + 检查点，符合"无人值守"目标。
5. **鲁棒性**：修复了推理模型空 content、max_tokens 截断、草稿截断三个真实 bug。

### ⚠️ 弱点与局限（诚实声明）

1. **论文数据是 LLM "幻觉"，未经真实验证** —— 这是最严重的局限。
   RAMQA 论文里的实验数据（EM/F1 精确到小数点）、表格、引用，**全部是 LLM 生成的，没有真实实验支撑**。审稿人虽然能指出"缺显著性检验""基线不公平"，但**无法验证这些数字的真伪**——因为审稿人也是 LLM，它同样无法跑实验、查证引用真实性。

2. **"审稿"是语义层面的，不是事实层面的**：审稿人能评判结构完整性、逻辑合理性、论证是否自洽，但**无法验证**：
   - 引用的论文是否真实存在
   - 实验数字是否真实
   - 与已有工作的对比是否属实

3. **收敛判断粗糙**：仅靠 `verdict` + `score` 阈值，没有区分"创新性、正确性、可复现性"等多维度的质量门控。

4. **迭代深度受限**：本次 max_rounds=2 时分数仅 5→6（离 accept 还有距离），说明 2 轮不够，需要更多轮才能真正收敛。

5. **成本高**：每轮要 2 次长文本 LLM 调用（生成论文 + 评审），单篇论文约 8-10 分钟 + 大量 token。

---

## 四、本质定位（一句话）

**这是一个「结构化写作 + 互评迭代」的强演示，而不是「产出可发表论文」的能力。**

它能产出一篇**"看起来专业、结构完整、逻辑自洽"**的论文草稿，且能通过多轮互评**持续改进结构完整性和论证质量**。但它产出的**事实性内容（数据、引用、对比）是未经证实的**，需要人类（或接入真实检索/实验工具）来做最终的事实核查。

---

## 五、改进方向（按优先级）

| 优先级 | 改进 | 解决的问题 |
|:---|:---|:---|
| 🔴 高 | 接入真实检索：审稿人/投稿人用 `web_search` 查证引用真实性 | 引用幻觉 |
| 🔴 高 | 接入真实实验执行：让"实验"章节的数据来自真实代码运行（已有 `phase_experiment` 可复用）| 数据幻觉 |
| 🟡 中 | 多维质量门控：创新性/正确性/可复现性分维度评分 | 收敛判断粗糙 |
| 🟡 中 | 主编（Editor）仲裁角色：多审稿人意见冲突时汇总决策 | 单一审稿人偏见 |
| 🟢 低 | 增加迭代轮数 + 更细的终止条件 | 收敛深度 |

---

## 六、结论

**功能本身成立且有效**：投稿人↔审稿人多轮协作确实能显著提升论文的**结构完整性和论证质量**（分数 5→6，且修改可验证），这是多智能体互评的核心价值，已实现并跑通。

**能力边界清晰**：当前是"会写、会改、会批"的**写作协作引擎**，不是"会做研究"的**科研引擎**。要跨越这条鸿沟，必须接入**真实检索 + 真实实验执行**，让"证据"来自外部世界而非 LLM 的想象。

---

*本报告基于真实端到端运行结果，非理论推演。*

## 七、改进后评估（v3：接入真实检索 + 事实核查 + 多维门控）

针对上述"最严重局限"（论文数据是 LLM 幻觉），实施了关键改进：

| 改进 | 效果 |
|:---|:---|
| 投稿人写作前 `web_search` 检索真实资料 | 基于真实文献写作，不虚构引用 |
| 审稿人评审前 `web_search` 检索做事实核查 | 输出 `fact_check`，逐条标注 `verified/unverified/suspicious` |
| 多维质量门控 | 分维度评分 `novelty/correctness/reproducibility/clarity` |

**真实端到端验证结果**（主题「检索增强生成的可信度与幻觉抑制」）：

1. **事实核查真实有效**：审稿人第 2 轮准确核实了真实文献——Lewis et al. 2020 (NeurIPS)、Ji et al. 2023 (ACM Computing Surveys)、Gao et al. RAG survey (arXiv:2312.10997)——均标 `verified` 并给出准确出处；同时识别出**重复引用**（[1]/[3]、[2]/[5] 标题相同）、**截断引用**（[4] 不完整）、**非学术来源**（CSDN 博客）、**文本重用风险**。

2. **投稿人诚实度质变**：审稿人明确确认"未虚构实验数据，明确标注为方法设计/待检验假设"——这与改进前（RAMQA 论文编造 EM/F1 精确到小数点）形成本质区别。

3. **多维评分提升**：novelty 4→5、reproducibility 7→8、clarity 6→7。

**改进后定位**：从"会写会改的写作引擎"升级为"**有据可查的写作引擎**"——事实核查让审稿人能够区分真实文献与幻觉引用，投稿人被约束为"基于真实资料写作、不编造数据"。

**仍存的局限**（诚实）：论文的"实验数据"目前是"待检验假设"而非"真实运行结果"。要彻底解决，还需接入**真实实验执行**（让方法在真实数据集上跑，产出真实指标）——这是下一步的自然延伸。
