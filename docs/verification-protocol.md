# 强制校验协议（Verification Protocol）

> 背景：体检发现系统"推演过重、独立检验空置"。本协议规定：**凡涉及"正确性声明"或"定量结论"的产出，交付前必须经过确定性校验。**
> 状态：v1，已生效。

---

## 一、核心原则

1. **正确性不来自生成方（LLM 自评），而来自确定性检验方。**
2. 确定性校验 = 不调用 LLM、用规则检查，是唯一不依赖"自问自答"的锚点。
3. 任何"看起来自洽"的报告，未经确定性校验，不得视为可信交付。

---

## 二、三类产出 → 对应校验工具

| 产出类型 | 强制校验工具 | 校验什么 |
|----------|--------------|----------|
| 含评估快照 / verdict / 分数 | `evidence_verifier` | 快照字段完整性、verdict 与 veto 一致性、分数自洽 |
| 文本 / 报告 / 分析产物 | `artifact_validator` | 结构完整性、数字自洽、引用可追溯、可解析性 |
| 关键判断存在分歧风险 | `multi_reviewer`（scores 模式） | 多视角分数分歧度（确定性计算） |

---

## 三、强制触发场景

以下场景**必须**在校验通过后才算完成：

1. 产出一份"系统诊断/体检/评估"报告；
2. 声称"改进了 X、提升了 Y"（需 effect_evaluator 快照 + evidence_verifier 校验）；
3. 产出含定量结论（百分比、分数、通过率）的文本；
4. 声称"修复了某个 bug"（需 safe_deploy / test_runner 验证，而非口头声称）。

---

## 四、禁止事项

- ❌ 不得以"我觉得对"代替校验；
- ❌ 不得在 evidence_verifier 报告"未通过"时仍宣称结论成立；
- ❌ 不得将"多视角评审"当作独立校验（它依赖 LLM，在本环境无独立客户端时仅能确定性降级）。
