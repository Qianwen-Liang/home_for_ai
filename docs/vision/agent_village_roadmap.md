# 智能体村 · 渐进式演进路线

> 决策已定：记忆采用**双层**（村公共 + 个人私有）；自治程度与进程模型均**渐进**。
> 本文档给出两条线交织后的具体路线。

---

## 一、三条演进线

### 线 A：自治程度（中心制 → 自治）

```
A1 中心制 ──→ A2 微自治 ──→ A3 半自治 ──→ A4 自治
(村长全权调度) (村民后台执行) (村民自主发起+审批) (村民自治,村长治理)
```

### 线 B：进程模型（共享实例 → 独立进程）

```
B1 共享实例 ──→ B2 持久化实例 ──→ B3 后台离线 ──→ B4 长驻进程 ──→ B5 ACP独立进程
(当前模式)   (独立状态文件)   (offline任务)   (message_bus通信) (外部可调用)
```

### 线 C：记忆（贯穿始终，双层）

```
C1 双层框架 ──→ C2 个人记忆积累 ──→ C3 双向沉淀 ──→ C4 声誉+治理
(公共+私有目录) (journal+私有条目) (自动写公共知识) (贡献+村规)
```

---

## 二、五阶段路线（两条线交织）

### 阶段 1：村落雏形 + 独立身份
- **线 A**：A1 中心制（村长统一调度，村民被动响应）
- **线 B**：B1 共享实例（当前模式，改动最小）
- **线 C**：C1 双层框架搭建

**动作**：
1. 建立 `village/` 骨架 + `constitution.md`（村规）
2. 为 8 个活跃村民建"家"目录 + `identity.md`（身份/能力/边界）
3. 统一 Agent 注册三处（registry/profile/默认注册）
4. 村民 `identity.md` 加载为独立 system prompt
5. 双层记忆目录：`commons/knowledge`（公共）+ `villagers/<id>/memory`（私有，初始为空）

**验收**：每个村民有独立身份文件 + 独立提示词 + 独立记忆目录；但运行仍是共享实例，村长全权调度。

---

### 阶段 2：状态持久化 + 个人记忆落地
- **线 A**：仍 A1 中心制，但村民开始有"自己的状态"
- **线 B**：B2 持久化实例（独立状态文件，重启可恢复）
- **线 C**：C2 个人记忆积累

**动作**：
1. 每个村民独立状态文件 `status.json`（状态/历史/当前任务）
2. 村民每次任务后追加 `journal.md`（个人日记）
3. 个人记忆 store（私有知识条目，按村民 ID 隔离，复用 knowledge 的 kind 三轨）

**验收**：村民重启后能恢复自己的状态和历史；个人记忆与公共知识物理分离；村长仍统一调度。

---

### 阶段 3：村民后台运行（微自治）
- **线 A**：A2 微自治（村长分配，村民后台独立执行，有"日常工作"雏形）
- **线 B**：B3 后台离线（任务通过 offline 工具独立运行）
- **线 C**：C3 双向沉淀

**动作**：
1. Monitor 村民的"定期巡检"做成 offline 任务（无人值守）
2. Researcher 村民的"定期调研"做成 offline 任务
3. 村民后台运行结果自动写个人 journal + 沉淀公共知识

**验收**：村民能在无人值守下完成分配任务；结果自动双向沉淀（个人记忆 + 公共知识）；这是第一次"村民像村民"——有自己的工作节律。

---

### 阶段 4：自主发起 + 社会协作（半自治）
- **线 A**：A3 半自治（村民可自主发起任务，向村长报告/请求批准）
- **线 B**：B4 长驻进程雏形（关键村民 Monitor/Debugger 有独立长驻进程，message_bus 通信）
- **线 C**：C4 声誉系统

**动作**：
1. 声誉系统（复用 audit_log + 贡献记录，村民协作评分）
2. 村民间协作协议（复用 orchestrator + blackboard）
3. Monitor 长驻巡检进程（主动发现问题并上报）
4. 村民"请求批准"机制（复用现有 request_approval）

**验收**：村民能主动报告问题、请求协作；声誉分反映贡献；村长从"事事亲为"转向"审批+仲裁"。

---

### 阶段 5：村民自治 + 外部互联
- **线 A**：A4 自治（村民自治，村长只治理和仲裁）
- **线 B**：B5 ACP 独立进程（村民可被外部编辑器直接调用）
- **线 C**：C4 完整村规治理

**动作**：
1. 村民 ACP 对齐（承接此前 ACP 评估文档）
2. 村规执行：积分、权限、仲裁（复用现有积分机制）
3. 外部编辑器接入（如 Zed 直接调用村民）

**验收**：村落可独立运转；村民自治协作；村长治理；外部可互联。

---

## 三、渐进的核心原则

1. **每阶段"双线各进一步"**：自治 + 进程模型同步渐进，但每阶段只各走一步，避免跳跃。
2. **记忆双层贯穿始终**：从阶段 1 就建立双层框架，后续只是"从空到满"的自然积累。
3. **可回滚**：每阶段都是增量，任一阶段停下，村落仍是"可用的前一个状态"。
4. **复用优先**：每个阶段复用已有成果（offline/orchestrator/audit_log/ACP 评估），而非新造轮子。
5. **村民逐步"活化"**：阶段 1-2 村民是"有身份的影子"；阶段 3 是"有节律的工人"；阶段 4-5 是"有自主性的村民"。

---

## 四、与"智能体精简建议"的关系

上一轮的"精简建议"（Evolver 降级、Debugger 修复逻辑指向引擎、Novelist 归档）是**阶段 1 的前置动作**——先让村民"身份干净、能力边界清晰"，再开始建村。顺序是：

```
精简智能体 → 阶段1 雏形 → 阶段2 持久化 → 阶段3 微自治 → 阶段4 半自治 → 阶段5 自治
```

---

## 五、一句话总结

> 渐进路线 = 让村民沿着"中心制→自治"和"共享实例→独立进程"两条线**同步但小步**地演进，每一阶段村民都更"像村民"一点：先有家（阶段1）、再有记忆（阶段2）、再有工作节律（阶段3）、再有自主性（阶段4）、最终自治且互联（阶段5）；双层记忆从第一天就贯穿。
