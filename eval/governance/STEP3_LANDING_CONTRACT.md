## 二、部分落地（接口就位，逻辑延后）

| # | 调研结论 | 来源 | 当前状态 | 延后原因 |
|---|---------|------|---------|---------|
| 1 | 统计异常检测（回声状态网络+CUSUM） | arXiv 2608.02464 | **不做** | 论文自证冷启动 AUROC 仅 0.527、不能热迁移，且确定性验证全面更优 |
| 2 | 执行血缘 + 哈希 trace ledger | arXiv 2607.14309 | **不做** | 属合规审计范畴，超出架构治理范围，且需持久化基础设施 |
| 3 | 分级干预总线（GEB） | arXiv 2604.05119 | **钩子预留** | 仅在 `on_threshold()` 中预留动作返回，不做完整干预编排 |

## 三、明确不落地（附理由）

| # | 调研结论 | 不落地理由 |
|---|---------|-----------|
| 1 | 完整 span 上下文传播 / 分布式追踪 | 单进程架构，无跨服务调用链；引入将增加复杂度而无收益 |
| 2 | 引入 opentelemetry SDK | 依赖缺失且与"零新增依赖"原则冲突；仅对齐命名即可保留未来兼容性 |
| 3 | 治理策略引擎（OPA 兼容） | 超出可观测性范围，属步骤 4（错误契约）之后的能力 |

## 四、事后审计方法

实现完成后运行：
```bash
python eval/governance/_audit_research_landing.py
```
该脚本应检查：
- 中间件中 OTel 属性/指标/异常命名是否全部出现
- 三个确定性验证函数是否存在且被调用
- 手工埋点是否已归零
- 是否引入了被禁止的第三方依赖

**任何一项为 ❌，即视为调研未落地。**

## 五、历史教训（本表的由来）

审计发现两处真实滑落：
1. **jsonschema 装了但没用** —— 步骤1 声称采用 JSON Schema 校验，实际手写字段检查。已通过新增 C7 断言补齐（契约测试 64 → 96）。
2. **`stub` / `activate_when` 只定义未生效** —— 已在代码中明确标注「预留-未生效」，避免虚报。

**结论：调研结论若不写进"可被脚本检出"的位置，就等于没做。**
