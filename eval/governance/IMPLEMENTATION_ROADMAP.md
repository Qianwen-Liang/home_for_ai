## 1. 契约测试网（Contract Test Matrix）

> **为什么必须第一**：步骤 2 要一次性改动 37 个分派分支，没有测试网等于蒙眼拆承重墙。

### 1.1 建立工具契约规范
- **动作**：定义所有工具必须满足的契约字段
  - 必填参数与类型、参数合法性边界
  - 错误处理：必须抛 `XxxError(RuntimeError)` 或返回结构化错误串
  - 超时行为、大结果行为、幂等性声明
- **产出**：`tests/contract/SPEC.md`
- **验收**：规范覆盖全部 16 个已注册工具，每项契约可被断言

### 1.2 编写契约测试矩阵
- **动作**：参数化测试，自动遍历 `agent1.ALL_TOOLS` 逐个验证
  - `test_param_validation`：缺参/错类型/越界 → 必须给友好错误而非崩溃
  - `test_error_contract`：故意触发错误 → 必须抛已知错误类型
  - `test_no_exception_leak`：工具入口绝不抛未捕获异常
  - `test_large_result`：大结果必须走摘要路径
- **产出**：`tests/contract/test_tool_contracts.py`
- **验收**：16 个工具 × 4 类契约 = 64 个断言全绿；对 legacy 工具同样可跑

### 1.3 基线记录与差异清单
- **动作**：跑一遍全量契约测试，记录当前不满足项
- **产出**：`eval/governance/contract_baseline.json`
- **验收**：所有不满足项已登记（作为步骤 5 的输入），且**不阻塞**后续步骤

**回滚点 R1**：测试文件为新增，删掉即回滚，零风险。

## 2. 声明式工具注册表（Declarative Registry）

> **核心杠杆**：把"改 3 处"变成"写 1 个装饰器"。

### 2.1 定义工具元数据模型
- **动作**：定义 `ToolSpec` 数据类
  ```python
  ToolSpec(name, definition, handler, errors: tuple[type,...],
           budget: ContextBudget, retryable: bool, idempotent: bool, tags: list[str])
  ```
- **产出**：`tools/registry.py`（新建）
- **验收**：`ToolSpec` 可完整描述现有 16 个工具的属性

### 2.2 实现注册与发现
- **动作**：
  - `@register_tool(spec)` 装饰器
  - 全局 `REGISTRY: dict[str, ToolSpec]`
  - `build_all_tools()` 返回稳定顺序的 `ALL_TOOLS`（**保持字节稳定**）
- **验收**：注册顺序确定、重复注册报错、`ALL_TOOLS` 输出与当前逐字符一致

### 2.3 分派层改造（关键步）
- **动作**：`execute_model_tool_call` 中 37 个 elif → 一次查表
  ```python
  spec = REGISTRY.get(name)
  if spec is None: → 未知工具友好提示
  result = spec.handler(arguments)
  ```
- **验收**：16 个工具全部可正常执行；未知工具提示不劣化；`test_web_search` / `test_self_check` 等既有测试全绿
- **风险**：中高 — 必须 `safe_deploy` 备份 + 契约测试全绿后才合并

### 2.4 恢复机制改造
- **动作**：legacy 工具的启用/停用从"改代码"改为"改配置"
  - `legacy_tools.json` 增加 `enabled` 字段
  - 启动时按配置组装 `ALL_TOOLS`
- **验收**：改配置即可启用/停用工具，无需改 `agent1.py`

**回滚点 R2**：保留旧 elif 分支代码于 `_legacy_dispatch()`，配置开关可切回。

## 3. 可观测性中间件（Observability Middleware）

### 3.1 统一执行拦截器
- **动作**：在注册表分派处包一层中间件，自动记录
  - 工具名、耗时、结果字符数、成功/失败、错误分类、参数规模
- **产出**：`tools/middleware.py`
- **验收**：新增工具**无需埋点自动获得**统计

### 3.2 收敛手工埋点
- **动作**：移除 `agent1.py` 中手工 `tool_monitor._monitor.record(...)` 调用
- **验收**：monitor 数据不丢失，`usage_analyzer` 输出正常

### 3.3 性能/体积画像
- **动作**：中间件按工具聚合，输出"慢工具 TOP / 大结果 TOP"
- **产出**：`eval/governance/perf_profile.json` 自动生成
- **验收**：能自动识别出 >3s 慢工具与 >20KB 大结果工具

**回滚点 R3**：中间件为可开关包装，关闭即回到直连。

## 4. 统一错误契约 + 全局上下文预算

### 4.1 三层错误模型
- **动作**：30 种工具错误 → 3 类
  | 类别 | 语义 | 处理 |
  |------|------|------|
  | `RETRYABLE` | 网络/超时/限流 | 自动重试 |
  | `FATAL` | 配置/环境/不可恢复 | 上报 + 诊断 |
  | `REJECTED` | 业务拒绝（路径不存在/参数越界） | 交模型自纠 |
- **产出**：`tools/errors.py`
- **验收**：每个现有错误类型有明确归类；`error_code` + 原始信息完整保留（分类不丢弃）

### 4.2 错误映射表
- **动作**：建立 `OldError → (Category, code)` 映射，一次性替换 `except` 元组手工登记
- **验收**：新增工具只需声明错误类型，不需改 `agent1.py`

### 4.3 全局上下文预算
- **动作**：统一 `ContextBudget`
  - 按剩余上下文动态分配单工具结果上限
  - 取代 read_file 的 20KB、run_command 的 20K 字符等各自阈值
- **验收**：所有工具共用同一预算策略；超限统一走"摘要 + 句柄"

### 4.4 契约回归
- **动作**：重跑契约测试矩阵，确认错误契约全部符合新模型
- **验收**：契约测试全绿；`contract_baseline.json` 的不满足项清零或明确豁免

**回滚点 R4**：错误映射表可回退，保留旧 `XxxError` 类定义不删除。

## 5. 模块精修（按需，不做全面铺开）

> 原则：**只修契约基线暴露的问题 + 实测性能问题**，不为"统一风格"而改。

### 5.1 knowledge 两阶段检索
- **问题**：语义模型就绪后查询仍需 10.6s（214 条全量算向量）
- **动作**：关键词预筛 top-30 → 语义精排
- **验收**：语义查询 < 1.5s，召回质量不降

### 5.2 契约基线不满足项修复
- **动作**：按 `contract_baseline.json` 逐项修复
- **验收**：清单清零或登记豁免理由

### 5.3 其余模块
- **原则**：无实测问题不改。18 个零调用 legacy 工具不做精修。

## 6. 验收与停止条件

### 6.1 全局验收指标
| 指标 | 目标 |
|------|------|
| 新增工具改动点 | **1 处**（仅声明） |
| 契约测试覆盖 | 100% 已注册工具 |
| 手工埋点 | **0 处** |
| 错误类型分类覆盖 | 100% |
| 既有测试 | 全绿 |

### 6.2 预注册失败判据
1. 任一步骤导致既有测试新增失败且 3 日内未修复 → 回滚该步骤
2. 步骤 2 后工具执行成功率下降 >2% → 回滚至 R2
3. 步骤 3 后 monitor 数据缺失 → 回滚至 R3
4. 步骤 4 后出现错误信息丢失（无法定位根因）→ 回滚至 R4
5. 连续 2 次验收不通过 → 停止推进，重新评估

### 6.3 每步固定动作
1. 写代码 → 2. 语法校验 → 3. 跑契约 + 既有测试 → 4. `safe_deploy` 部署（失败自动回滚）→ 5. 记录知识 + 审计日志
